# TokenScope

TokenScope помогает сравнивать публичные предложения токенов и доступа к нейросетям на FunPay: цену за 1 млн токенов, объём, условия продавца и историю цен. Поддерживаются категории DeepSeek, OpenCode, ChatGPT, Gemini, Claude и Kimi.

Проект работает в двух режимах: **локальный сервер с загрузкой данных** и **статический сайт GitHub Pages со снимком каталога**. Данные продавцов и автоматический разбор описаний могут быть неполными; перед покупкой проверяйте само объявление.

## Быстрый запуск на компьютере

Установите [Node.js 24](https://nodejs.org/en/download), откройте терминал в папке проекта и выполните:

```bash
npm start
```

Откройте <http://127.0.0.1:8787/>. Остановить сервер можно сочетанием `Ctrl+C`. Сервер использует встроенные модули Node.js; внешних npm-зависимостей нет.

В локальном режиме сервер получает каталог FunPay, догружает описания и публичные отзывы продавцов. Подключение к FunPay требует сети и может завершиться ошибкой или блокировкой со стороны источника.

## GitHub Pages или локальный запуск

| Возможность | Локально: `npm start` | GitHub Pages |
| --- | --- | --- |
| Каталог | Получается сервером с FunPay | Последний опубликованный снимок |
| Фильтры, сортировка, статистика | Выполняются сервером | Вычисляются в браузере по снимку |
| Описания | Могут догружаться с FunPay | Только сохранённые в снимке |
| История цен | Накапливается в локальных данных | История, попавшая в сборку |
| Кнопка обновления | Запрашивает обновление на сервере | Перечитывает опубликованный снимок |
| Отзывы продавца внутри сайта | Доступны через локальный сервер | Живая загрузка недоступна; переход в профиль FunPay |
| Фильтры отсутствия низких оценок | Проверяют публичные отзывы профиля | Отключены; старые ссылки с этим условием показывают пояснение |
| Node.js на хостинге | Нужен запущенный процесс | На Pages его нет; Node.js используется только при сборке в Actions |

**Pages не показывает данные в реальном времени.** Цена, наличие, онлайн-статус и число отзывов относятся к моменту сбора. Расписание Actions раз в 30 минут — попытка обновления, а не обещание точности или доставки через 30 минут. Фактическую свежесть проверяйте по времени снимка и состоянию последнего запуска.

GitHub Pages публикует статические файлы; серверный код там не исполняется: [официальное описание Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

## Что можно делать

- Выбрать категории, модели и готовый набор фильтров; сохранить свой набор в браузере.
- Видеть выбранную площадку FunPay в блоке сервисов. Другие площадки помечены «Coming soon» и пока недоступны.
- Сравнить пакеты по цене за 1 млн токенов, временный безлимит — по цене часа.
- В разделе «Цена и объём» выбрать любое количество, точный объём или диапазон. Например, «Ровно столько» и `10М` оставят лоты ровно на 10 млн токенов, а не несколько меньших пакетов.
- Фильтровать по цене, объёму, рейтингу и стажу продавца, автовыдаче, бонусам, возврату, сроку доступа и схеме списания.
- Смотреть описания с подсветкой заявленных преимуществ, ограничений, сроков и формул.
- Скрывать продавцов, переключать плитку и список, копировать ссылку с фильтрами.
- В локальном режиме открывать публичные отзывы продавца и проверять отсутствие выбранных низких оценок.

Фильтры собраны в четыре раздела: «Предложение», «Цена и объём», «Продавец», «Условия». Дублирующие переключатели убраны; редкие настройки раскрываются отдельно. Фон сайта — чистый чёрный, акценты — светло-зелёные.

Подробности и ограничения распознавания сохранены в [справочнике API и фильтров](docs/API.md).

## Команды и контракт сборки

Рекомендуемая версия Node.js для проекта и CI — **24**.

| Команда | Что делает | Нужна сеть |
| --- | --- | --- |
| `npm start` | Запускает локальный сервер на порту 8787 | Для получения данных FunPay |
| `npm test` | Выполняет детерминированные тесты парсера и сервисов | Нет |
| `npm run build` | Создаёт статический сайт в `dist/` из локальных данных | Нет |
| `npm run snapshot` | Выполняет `node tools/collect-snapshot.js`, затем `npm run build` | Да, для сбора снимка |
| `npm run preview` | Показывает готовый `dist/` на `http://127.0.0.1:4173/tokenscope/` | Нет |
| `npm run test:pages` | Проверяет статическую сборку | Нет |
| `npm run test:pages:ui` | Проверяет статическую версию в браузере | Нет |

`npm run build` сам не обращается к FunPay. Он использует `data/cache.json` и доступные локальные историю и описания. Если исходных данных ещё нет, допустима честная пустая выдача с указанием отсутствия снимка: тестовые цены и продавцы не подставляются.

Для первой сборки с данными:

```bash
npm test
npm run snapshot
```

Если нужен только статический каркас без сети:

```bash
npm run build
```

Публикуется содержимое **`dist/`**, а не весь проект. Для проверки готовой сборки выполните `npm run preview` и откройте <http://127.0.0.1:4173/tokenscope/>. Открытие `index.html` через `file://` не заменяет HTTP-проверку загрузки снимка.

## Как разместить на GitHub

1. Создайте публичный репозиторий **`tokenscope`** без автоматического README, `.gitignore` и лицензии: они уже входят в проект.
2. Перед загрузкой проверьте `.gitignore` и список файлов. Исходные `data/`, `dist/`, секреты, локальные логи и скриншоты в репозиторий не добавляйте.
3. Загрузите исходники вместе с **`.github/workflows/pages.yml`**. Рекомендуется Git: скрытую папку `.github` легко пропустить при загрузке через браузер.
4. Откройте репозиторий: **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. Во вкладке **Actions** дождитесь успешного запуска workflow или запустите его вручную. Адрес опубликованного сайта появится в **Settings → Pages**.

Полная инструкция с командами Git, вариантом загрузки через браузер, первым запуском и разбором ошибок: **[docs/GITHUB_PAGES.md](docs/GITHUB_PAGES.md)**. Настройка источника описана также в [документации GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

Workflow `.github/workflows/pages.yml` собирает и публикует сайт из `main` при push, ручном запуске и по расписанию раз в 30 минут. Он использует Node.js 24 и пытается обновить публичный снимок. Для каждой категории нужны свежие лоты либо пригодные сохранённые данные с датой сбора. Если хотя бы одна категория осталась без данных, сбор завершается ошибкой до записи снимка и публикации — прежний сайт сохраняется. При использовании старых данных их даты и предупреждение остаются видны; время неудачной попытки не выдаётся за время обновления цен.

После успешного сбора каталог и история сохраняются в Actions cache **до** сборки и загрузки сайта. Кэш не является постоянным архивом: если он утрачен, потребуется полный сбор всех категорий, а история начнёт накапливаться заново.

Снимок находится в `dist/snapshot.json`; для быстрой загрузки браузер использует сжатую копию `dist/snapshot.json.gz` (при отсутствии поддержки распаковки — обычный JSON): `updatedAt` обозначает свежесть данных, `builtAt` — время сборки, `lastAttemptAt` — последнюю попытку сбора; `partial`, `refreshError` и даты категорий помогают отличить неполные или устаревшие данные.

## Данные и публикация

Рабочая папка `data/` создаётся автоматически:

- `cache.json` — последний снимок лотов;
- `history.json` — точки истории цен;
- `descriptions.jsonl` — загруженные описания;
- `reviews.json` — локальный кэш проверок оценок продавцов; тексты страниц отзывов хранятся в памяти локального сервера.

`data/` и `dist/` исключены из Git. В Pages-артефакт попадают подготовленные для сайта публичные данные: **любой посетитель сможет их скачать**. Не добавляйте в исходные данные, артефакты или логи токены, cookies, пароли, приватные переписки и другие секреты. Сырые локальные кэши, диагностические логи и скриншоты не публикуйте; сборку `dist/` перед публикацией тоже нужно проверить.

Снимок не переносит на проект права на объявления, отзывы или товарные знаки третьих лиц. Ссылки на FunPay ведут на внешний сайт.
