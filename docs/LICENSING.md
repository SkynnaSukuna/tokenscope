# Какую лицензию выбрать для TokenScope

[Главная инструкция](../README.md) · [Размещение на GitHub](GITHUB_PAGES.md)

Для открытого проекта с разрешённым повторным использованием в корень добавлен **[LICENSE](../LICENSE)** с полным стандартным текстом **MIT**:

```text
Copyright (c) 2026 TokenScope contributors
```

Указана общая атрибуция участников проекта. Перед публикацией владелец должен подтвердить, что может лицензировать включённый код и материалы, и при необходимости указать действительных правообладателей. Русский текст ниже поясняет выбор; полный применимый текст MIT находится в `LICENSE`.

## Почему MIT

Выбирайте MIT, если хотите разрешить другим использовать, изменять и распространять код, включая коммерческие проекты и закрытые производные версии. При распространении копий или существенных частей кода нужно сохранять уведомление об авторских правах и текст разрешения. В MIT есть отказ от гарантий и ограничение ответственности в формулировках самой лицензии. [Текст и краткая характеристика MIT](https://choosealicense.com/licenses/mit/)

Для небольшого открытого инструмента это простой разрешительный вариант. Он не требует от каждого пользователя публиковать изменения, поэтому не подходит, если именно обязательная открытость производных версий — ваша цель.

## Когда рассмотреть другой вариант

| Намерение владельца | Что рассмотреть |
| --- | --- |
| Разрешить широкое повторное использование с минимумом условий | MIT — текущий вариант |
| Требовать исходный код распространяемых производных работ под условиями GPL | [GPL-3.0](https://choosealicense.com/licenses/gpl-3.0/) |
| Требовать предоставления соответствующего исходного кода пользователям изменённой версии, взаимодействующим с ней по сети, при выполнении условий лицензии | [AGPL-3.0](https://choosealicense.com/licenses/agpl-3.0/) |
| Не давать общее разрешение на повторное использование | Отдельные проприетарные условия и подходящий способ распространения |

GPL-3.0 и AGPL-3.0 не запрещают коммерческое использование; они накладывают дополнительные обязательства. Окончательные требования определяются полными текстами, способом использования и включёнными компонентами, а не одной строкой таблицы.

Публичный репозиторий сам по себе не заменяет лицензию. GitHub объясняет, что без неё по умолчанию сохраняются авторские права, при этом публичность репозитория даёт пользователям GitHub предусмотренные сервисом возможности просмотра и fork. Для закрытого проекта публичный репозиторий и MIT не соответствуют цели ограничить доступ к исходникам. [GitHub: Licensing a repository](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

## Границы лицензии

MIT в этом репозитории предназначена для кода и документации TokenScope в пределах прав, которыми распоряжаются их правообладатели. Она **не должна трактоваться как передача прав** на FunPay, названия сервисов, товарные знаки, тексты объявлений, отзывы продавцов или другие сторонние материалы.

Не удаляйте существующие уведомления об авторских правах и лицензиях стороннего кода. Если позже добавятся библиотеки, изображения, шрифты или заимствованные фрагменты, отдельно проверьте их условия. Выбор MIT для собственного кода не заменяет разрешение на стороннее содержимое или условия работы с источником данных.

Это руководство помогает выбрать направление и не даёт юридической гарантии пригодности лицензии для конкретной ситуации. Если важны спорные права, ограничения работодателя или совместимость нескольких лицензий, решение следует проверить с квалифицированным специалистом.

## Что сделать владельцу до публикации

1. Подтвердить намерение открыть проект под MIT либо выбрать другой вариант до распространения.
2. Проверить права на собственный код и включённые сторонние материалы; сохранить нужные уведомления.
3. Проверить год и атрибуцию в `LICENSE`. Сейчас указаны **2026** и **TokenScope contributors**.
4. Сохранить полный стандартный текст выбранной лицензии в корне репозитория и согласовать с ним упоминание в README и метаданных пакета. `npm run build` копирует этот же файл в `dist/LICENSE`, чтобы уведомление распространялось с опубликованным кодом сайта.
5. При создании репозитория GitHub не выбирать вторую автоматически добавляемую лицензию поверх подготовленного файла.
