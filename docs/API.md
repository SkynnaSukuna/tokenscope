# API, фильтры и проверки TokenScope

[Главная инструкция](../README.md) · [GitHub Pages](GITHUB_PAGES.md)

Этот справочник описывает локальный сервер, запущенный командой `npm start`. Примеры `/api/...` относятся к <http://127.0.0.1:8787/>. GitHub Pages публикует статические файлы и **не предоставляет HTTP API локального сервера**: поддерживаемая часть фильтров и статистики выполняется в браузере по опубликованному снимку. Новые описания и отзывы на Pages с FunPay не догружаются.

## HTTP API локального сервера

| Запрос | Назначение |
| --- | --- |
| `GET /api/offers` | Список лотов с фильтрами, статистикой и пагинацией |
| `GET /api/meta` | Категории, модели и счётчики |
| `GET /api/offer?id=...` | Одно предложение и его описание |
| `GET /api/reviews?seller=...&sort=worst&rating=0` | Публичные отзывы продавца |
| `GET /api/history?cat=all` | История цен |
| `POST /api/refresh` | Принудительное обновление каталога с FunPay |
| `POST /api/enrich` | Постановка описаний в очередь |
| `GET /api/health` | Состояние сервера |

`GET /api/offers` возвращает `updatedAt`, `total`, `page`, `pageSize`, `pages`, `items`, `stats`, сведения о загрузке описаний `desc`, `history`, `reviewCheck` и `refreshError`. Дата обновления относится к данным; ошибка получения источника не превращает старый снимок в новый.

### Основные параметры списка

Списки категорий, моделей и идентификаторов разделяются запятой. Булевы параметры включаются значением `1`.

| Параметр | Значение |
| --- | --- |
| `cat` | Идентификаторы категорий из `/api/meta`; без значения — все |
| `model` | Имена моделей из `/api/meta` |
| `q` | Поиск по названию, модели, продавцу и загруженному описанию |
| `need` | Положительное число токенов, требуемое ровно в одном лоте |
| `minStars`, `minReviews`, `minAgeMonths` | Минимальный рейтинг, число отзывов и стаж в месяцах |
| `auto`, `online` | Автовыдача и онлайн-статус |
| `minPriceM`, `maxPriceM` | Границы цены за 1 млн токенов |
| `minLotPrice`, `maxLotPrice` | Границы цены лота |
| `minTokens`, `maxTokens` | Границы объёма токенов |
| `noRateLimited`, `noCredits` | Исключение распознанных ограничений и кредитов |
| `offerType`, `minDuration`, `maxDuration` | Тип и срок доступа; см. ниже |
| `inputOutput` | Схема списания: `any`, `only`, `exclude` |
| `noReviewStars` | Выбранные оценки `1,2,3`, отсутствие которых проверяется по профилю |
| `sellersExclude`, `sellersInclude`, `offersExclude` | Исключаемые/включаемые идентификаторы продавцов и исключаемые лоты |
| `page`, `pageSize` | Страница от 1; размер по умолчанию 40, ограничен диапазоном 10–200 |
| `sort` | Сортировка; по умолчанию `priceM` |

Другие ограничения интерфейса передаются параметрами `bonus`, `oneToOne`, `refund`, `onlyDesc`, `qtyMode`, `qtyMin`, `qtyMax`, `unitMin`, `unitMax`, `unitKnown` и `exactTokens`. Точную ссылку с текущими значениями можно получить кнопкой копирования подборки в интерфейсе.

### Точный объём

В разделе «Цена и объём» выберите «Количество токенов → Ровно столько». Поле оставляет только лоты ровно на указанный объём: 1М, 5М, 10М, 50М, 100М, 500М, 1 млрд или своё число. Лоты меньшего и большего размера, безлимит, кредиты и неизвестный объём исключаются. Несколько меньших лотов в пакет не складываются; при отсутствии точных совпадений выдача пустая.

Режим «В диапазоне» открывает границы объёма, а «Любое количество» снимает точный объём и диапазон. При смене режима прежнее несовместимое условие очищается. Сохранённые ссылки и наборы восстанавливают нужный режим; если старая ссылка одновременно задаёт `need` и диапазон, в интерфейсе приоритет у точного объёма. Параметры прямого API не менялись.

Пример: `/api/offers?need=10000000` — ровно 10 млн токенов в одном лоте.

Интерфейс проверяет числа и границы диапазонов до запроса, понимает `10 000 000`, `1,5М`, `2k`. Неверный ввод не попадает в ссылку и фоновые запросы. В прямом API-запросе используйте числовое значение в токенах, например `10000000`.

## Отзывы и фильтры оценок

### Просмотр отзывов

`GET /api/reviews?seller=...&sort=worst&rating=0` получает публичные отзывы всего профиля продавца, а не только выбранного товара.

- `rating=1..5` ограничивает оценку; `0` означает все оценки.
- `sort=worst` — сначала плохие; `newest` — новые; `best` — хорошие.
- `cursor` продолжает историю. Он привязан к продавцу, оценке и порядку.
- `refresh=1` заново загружает первую страницу.

Ответ содержит `items`, `summary`, `hasMore`, `nextCursor`. В `summary.counts` неизвестное число — `null`, а `minimumCounts` задаёт известную нижнюю границу. Точный ноль появляется только после проверки соответствующей оценки; каждая оценка имеет собственный срок проверки. Проверки оценок кэшируются на 30 минут в `data/reviews.json`, отдельно для каждой звезды; тексты страниц отзывов кэшируются только в памяти локального сервера.

В режиме «сначала плохие» страницы запрашиваются последовательно по группам 1★ → 5★, поэтому низкие оценки из старой истории не теряются за новыми хорошими отзывами. FunPay часто скрывает имена покупателей и публикует относительные даты — эти данные не выдумываются.

Диалог отзывов поддерживает продолжение истории, фильтр оценки и поиск по уже загруженным отзывам. Ответ продавца показан отдельно. Положительные и критические фразы выделяются зелёным и красным; учитываются отрицания, исходный текст сохраняется.

### Отсутствие оценок 1–3★

`/api/offers?noReviewStars=1,2,3` оставляет продавцов без выбранных оценок. Флажки «Без отзывов на 1★», «Без отзывов на 2★» и «Без отзывов на 3★» можно сочетать.

Проверка использует фильтр звёзд самого FunPay; отсутствие нужной оценки подтверждается только распознанным пустым ответом соответствующей группы. Общий рейтинг 5★ и процентная диаграмма не доказывают отсутствие плохих отзывов. Неизвестная оценка, ошибка и просроченная проверка не считаются отсутствием жалоб.

Непроверенные профили догружаются в фоне; `reviewCheck` содержит число проверенных, ожидающих и ошибочных проверок. При первом включении выдача пополняется по мере проверки, рядом показан прогресс. Фильтр применяется до статистики, сортировки и пагинации и сочетается с `need=10000000` и другими условиями.

`sort=reviewsAsc` сортирует по числу отзывов по возрастанию, `starsAsc` — по рейтингу от меньшего к большему; неизвестный рейтинг идёт в конце.

**На GitHub Pages новых проверок нет.** Живые отзывы нужно открывать по внешней ссылке на профиль FunPay. Если сборка сохранила ранее полученную сводку, это не заменяет новую проверку и не подтверждает отсутствие низких оценок после истечения её срока.

## Формула списания токенов

`GET /api/offers?inputOutput=only` оставляет лоты, где распознана схема «вход + выход», а `inputOutput=exclude` исключает такие лоты. `any` или отсутствие параметра показывает все; неизвестные значения параметра приводятся к `any`. Условие применяется до статистики и пагинации, сочетается с остальными фильтрами и сохраняется в ссылке.

Распознаются `input + output`, `(input + output) × 1.5`, «вход + выход», «входящие + исходящие токены» и словесный учёт входа и выхода в контексте списания. Явный множитель необязателен. В ответе API и на карточке признак обозначается `flags.inputOutput`.

Это разбор названия и описания продавца: «без формулы» означает отсутствие распознанного совпадения, а не подтверждённое отсутствие такого списания у продавца. Точную ставку и условия кэширования смотрите в описании.

## Временный доступ и безлимит

`GET /api/offers` принимает параметры:

| Параметр | Значения |
| --- | --- |
| `offerType` | `any`, `tokens`, `unlimited`, `timed`, `excludeTimed`, `excludeUnlimited`, `credits` |
| `minDuration`, `maxDuration` | Положительные границы срока в **минутах**, включительно |
| `sort` | `priceHour` — цена часа по возрастанию; `duration` — срок по возрастанию |

Например, `/api/offers?offerType=timed&minDuration=60&maxDuration=60&sort=priceHour` — безлимит ровно на час; `offerType=excludeTimed` — убрать безлимит с распознанным сроком. Старые ссылки `unlimitedOnly=1` поддерживаются.

Ответ для каждого лота содержит `accessType` (`tokens`, `unlimited`, `credits`, `other`), `durationMinutes` и `pricePerHour`. Цена часа считается только для безлимита с распознанным сроком. Неизвестные значения — `null`; при сортировке они идут в конце. Лоты с неизвестным сроком не проходят заданную границу, но остаются в выдаче без временного фильтра.

Распознаются английские и русские обозначения: `unlimited for 1h`, `на 1 час`, `60 min`, `сутки`, `неделя`, `месяц`. Неделя равна 7 дням, месяц без календарной даты — 30 дням. Гарантия, срок ответа/выдачи, `24/7`, стаж и периодические квоты не считаются сроком доступа. Это разбор текста продавца, а не подтверждение условий площадкой; окончательные условия следует смотреть в объявлении.

Для временного безлимита карточка показывает срок и цену часа, для пакета — объём и цену за 1М. Безлимит и подписки не участвуют в расчёте цены за токены.

## Подробности фильтров и интерфейса

Сейчас источником предложений служит только FunPay: в блоке площадок она включена постоянно, а другие площадки помечены «Coming soon» и недоступны для выбора. Категории DeepSeek, OpenCode, ChatGPT, Gemini, Claude и Kimi относятся к каталогу FunPay.

Кроме выбора категорий и моделей, доступны:

- цена за 1М и цена самого лота;
- объём лота, объём за 1 шт. и кратность;
- рейтинг продавца, число отзывов и стаж на сайте;
- автовыдача, онлайн-статус, безлимит, отсутствие суточных лимитов и кредитов;
- тип предложения: пакеты токенов, безлимит, безлимит на время, исключение временного безлимита, кредиты и подписки;
- срок безлимита: 1 ч, 3 ч, 24 ч, 7 дней или свой диапазон в минутах, часах и днях;
- сортировка временного доступа по цене часа или сроку;
- бонусы, возврат, «1 токен = 1 человек»;
- схема списания «(вход + выход) × множитель»: все, с формулой или без формулы;
- наличие в лоте, если продавец явно указал «в наличии N шт»;
- скрытие нежелательных продавцов.

Панель состоит из четырёх основных разделов: «Предложение», «Цена и объём», «Продавец», «Условия». Дублирующий блок быстрых переключателей убран: каждое условие настраивается в одном месте. Конкретные модели, точность объёма и наличие, проверка низких оценок и загрузка описаний раскрываются отдельно. Площадки и скрытые объявления находятся в дополнительном пункте внизу панели. Поля срока видны для безлимита или когда срок уже задан ссылкой.

Наборы «Выгодные», «Надёжные», «Крупный объём», «Безлимит на 1 ч» и «Без ожидания» помогают начать подбор. Набор сохраняет поиск, категории, модели, скрытых продавцов и выбранные ограничения отзывов, а остальные условия заменяет. «Надёжные» в локальном режиме дополнительно включает отсутствие оценок 1–3★; на Pages эта дополнительная проверка отключена. «Без ожидания» включает автовыдачу и онлайн-статус по имеющимся данным, а не гарантирует моментальную выдачу.

Свой набор можно сохранить под именем через «Сохранить набор», применить повторно, перезаписать или удалить. Он хранится в этом браузере, не синхронизируется между устройствами и может пропасть после очистки данных сайта. Для передачи подборки другому человеку используйте копирование ссылки с фильтрами.

В моделях есть поиск; отдельный активный чип снимает только выбранную модель. Группы фильтров сворачиваются и показывают число активных условий, на мобильных фильтры открываются шторкой. На компьютере боковую панель можно убрать кнопкой «Скрыть» или «Фильтры» и вернуть кнопкой «Фильтры»; выбор сохраняется в браузере.

Карточки имеют переключатель «Плитка / Список». До 599 px используется одна колонка, с 600 px — адаптивная сетка с шириной карточки от 280 px. Открытое описание увеличивает высоту карточки. Фон TokenScope — чистый чёрный (`#000000`), поверхности нейтральные тёмные, основные акценты светло-зелёные.

Сводка включает медиану, среднюю, минимум и диапазон цен. История представлена графиком и лентой диапазона. Ссылка на подборку сохраняет выбранные фильтры.

### Описания и подсветка

Описание лота можно раскрыть без перехода на FunPay. В предпросмотре и полном описании важные фразы подсвечиваются:

- зелёным — заявленные преимущества;
- красным — ограничения и риски;
- жёлтым — сроки, объёмы, число моделей, формулы списания и место просмотра баланса.

Выделяются условия кэширования: «кэшированный вход — за половину», «кэшерование - 50 %», `cached input`, а также ограничения и доплаты. Учитываются отрицания вроде «гарантии нет» и «возврат не предусмотрен». Подсветка основана на тексте продавца и не подтверждает его обещания.

Локальный сервер постоянно догружает описания в фоне; интерфейс повторно запрашивает выдачу каждые 3 минуты. На Pages работают только описания из снимка, а повторный запрос опубликованных файлов не собирает новый каталог FunPay.

## Проверки

Быстрые тесты парсера, фильтров, сервиса отзывов и подсветки без запуска сервера:

```bash
npm test
```

Детерминированная браузерная проверка фильтров, скрытия панели и подсветки на локальных фикстурах:

```bash
npm run test:access
```

Детерминированная браузерная проверка отзывов: фильтры оценок, порядок, пагинация, безопасная подсветка, ошибки/повторы, клавиатура и мобильный просмотр:

```bash
npm run test:reviews
```

Интерактивная проверка UI:

```bash
npm run test:ui
```

Она поднимает headless Chrome и проверяет загрузку списка, карточки, фильтры, пресеты, описания, скрытие продавцов, пагинацию, сохранение состояния и историю цен. Результаты и число проверок печатаются после каждой команды. `npm test` выполняется без сети; проверки `test:access` и `test:reviews` используют локальные фикстуры и требуют установленный Chrome или Edge.

Проверки статической сборки и её браузерного режима:

```bash
npm run test:pages
npm run test:pages:ui
```

Для всех проверок рекомендуется Node.js 24, как в Actions и `.nvmrc`; браузерным тестам также нужен Chrome или Edge. Отдельный предпросмотр готового `dist/` запускается командой `npm run preview` по адресу <http://127.0.0.1:4173/tokenscope/>.

Скриншот локально запущенного сайта:

```bash
node tools/shot.js http://127.0.0.1:8787/ 1440 1600 .probe/shot.png 5000
```

Скриншоты и результаты диагностики остаются локальными; перед публикацией убедитесь, что они не попали в Git или Pages-артефакт.
